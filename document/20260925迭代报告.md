

# DeepSeek 通用工具 · 迭代记录

记录范围：从最初 `prompt_tool_test.py` 到当前三模式统一版本。
记录格式：按里程碑编号，每个节点写核心变动、影响文件、决策理由。

---

## v0.0 · 起点

**状态**：旧版 `prompt_tool.py`，anima / minimax 专用后处理脚本。

**特征**：
- `target` 硬编码在代码里，`/anima` `/minimax` 切换靠重置上下文。
- 无通用聊天能力，system prompt 永远是 anima 或 minimax。
- 有 `/trim` `/undo` `/clear` `/save` `/history` `/thinking` `/reverse`。
- 有 token 日志、成本估算，但价格硬编码。
- 模型名 `deepseek-flash`，`base_url` 固定。
- 单文件 800+ 行，`validate_output` 对通用聊天会误报。

**决策**：不修旧脚本，重写为模块化结构。

---

## v0.1 · 设计阶段

**核心决策**：
1. 方案 C：通用聊天主入口 + anima/minimax 可选管道，共享底层。
2. 用 Chat Completions，不用 Responses API。
3. 默认模型 `deepseek-flash`，默认思考关闭，`effort=low`。
4. 多会话用 JSONL 分文件，不上 SQLite。
5. 鲸鱼娘 system prompt 内置，身份边界写进 prompt。
6. 目录结构：`core/` + `chat/` + `pipeline/`。

**校准**：DeepSeek 官方文档确认——`deepseek-flash`、`deepseek-v4-pro`、`thinking.type`、`reasoning_effort`、`delta.reasoning_content`、1M 上下文、图片理解。

**产出**：设计文档 v0.1。

## M1 · 核心层 + 流式聊天

**新增文件**：

```text
deepseek_tool/
├── core/
│   ├── config.py       # 配置集中，WHALE_GIRL_PROMPT 内置
│   ├── client.py       # DeepSeekClient.stream_chat()
│   ├── token_log.py    # JSONL 日志 + 汇总
│   └── ui.py           # Rich 输出、stream_callback
├── chat/
│   └── main.py         # 流式聊天循环
└── key.env
run.py                  # 启动入口
```

**核心能力**：
- 流式聊天，`reasoning` 灰色斜体、`content` 正常输出。
- `max_tokens` 根据 `thinking_enabled` 动态切换：关闭 8192，开启 32768。
- token 记录到 `token_log.jsonl`。
- 启动显示最近 7 天消耗。

**内置命令**：`/thinking on|off`、`/effort low|high|max`、`/clear`、`/help`、`/exit`。

**修复**：
1. `run.py` 路径问题：从包内挪到项目根。
2. `key.env` 定位：`base_dir` 指向项目根。

**验收**：截图显示鲸鱼娘自我介绍正常、思考内容可见、token 统计正确。

## M2 · 多会话管理

**新增文件**：

```text
core/session.py         # Session + SessionManager
chat/commands.py        # 命令处理
sessions/               # 会话数据
history/                # 导出归档
```

**数据格式**：
- `sessions/<id>.jsonl`：第一行 meta，后续消息。
- meta 含 `id` / `title` / `mode` / `model` / `system_prompt` / `created` / `updated`。

**新增命令**：
`/new` `/list` `/load` `/title` `/undo` `/trim` `/clear` `/save` `/cost`。

**行为变化**：
- 启动自动加载最近会话。
- 每次回复后自动保存。
- `//` 转义普通消息。
- `/anima` `/minimax` 占位（M3 实现）。

**验收**：会话列表、加载、重命名、导出、撤销、修剪全部正常。

## M2.1 · 启动参数

**新增参数**：

```text
--thinking on|off
--effort low|high|max
--model <名>
--session <ID>
--new
--title <标题>
```

**调整**：
- `config.py` 默认 `DEEPSEEK_THINKING` 从 `"1"` 改 `"0"`。
- `start.bat` 一键启动。
- 砍掉 `--exec`（无必要，手动敲命令更灵活）。

**决策**：启动参数只处理“每次启动固定不变”的东西，交互命令手动敲。

## M3 · 后处理管道

**新增文件**：

```text
pipeline/
├── __init__.py
├── anima.py       # ANIMA_SYSTEM + validate_anima + split_anima_blocks
├── minimax.py     # MINIMAX_SYSTEM + validate_minimax
└── runner.py      # run_pipeline + interactive_loop
```

**修改**：
- `core/client.py` 加非流式 `chat()`。
- `chat/commands.py`：`/anima` `/minimax` 返回 `enter_pipeline`。
- `chat/main.py`：检测 `enter_pipeline` 调 `interactive_loop`。

**管道命令**：`/back` `/exit` `/quit` `/stream on|off` `/help`。

**决策**：管道不共享聊天上下文，独立跑，非流式（校验需完整输出）。

## M3.1 · 管道流式化

**变动**：
- `run_pipeline` 支持 `stream` 参数，默认流式。
- `/stream on|off` 切换。
- 输出实时打印，最后校验。

**决策**：校验天然需要完整文本，只能“流式输出 + 最后校验”，不能边流边校验。

---

## M3.2 · 管道命令扩展

**新增命令**：

```text
/mode anima|minimax      切换管道
/file <路径> [要求]       从文件读取
/append <要求>            基于上一条输出修订
/history                  查看处理历史
/save                     导出处理历史
/clear                    清空处理历史
/thinking /effort         共享 config
```

**实现细节**：
- `state[mode]` 独立维护 `last_input` / `last_output`。
- `/append` 用选项 A：system + 上次输入 + 上次输出 + 新要求。
- `/file` 用选项 C：引号优先，无引号按第一个空格切分，路径尾部 `rstrip`。
- `/history` 跨 mode 显示。
- 帮助面板改紫色（magenta），与聊天青色区分。
- 未知命令兜底：管道里打 `/xxx` 提示未知命令，不发给模型。

**决策**：
- 删 `/exit`（管道内不退出程序，只 `/back`）。
- `/stream` 保留开关。

## v0.3 · 三模式统一重构（重大）

**核心变动**：chat / anima / minimax 三个同级模式。

**架构**：
- 三模式各自有 `Session`，全部持久化到 `sessions/`。
- 统一模式循环，`current_mode` 变量控制。
- `sessions = {"chat": ..., "anima": ..., "minimax": ...}` 内存持有。

**命令统一**：

| 类别 | 命令 |
|---|---|
| 模式切换 | `/chat` `/anima` `/minimax` |
| 会话管理（三模式通用） | `/new` `/list` `/load` `/title` `/undo` `/trim` `/save` `/cost` |
| 管道专属 | `/clear`（聊天侧禁用） |
| 三模式通用 | `/file` `/thinking` `/effort` `/help` `/exit` |

**删除命令**：
- `/back` `/mode` `/anima` `/minimax` 的旧入口逻辑
- `/append`（管道默认带上下文后，普通输入即 append 语义）
- `/history`（靠鼠标滚轮看）
- `//` 转义（无需求）
- 聊天侧 `/clear`（改为手动删文件或 `/new`）

**管道行为变化**：
- 管道默认带上下文，历史发给模型。
- 每次回复后显示“管道默认开启上下文，/clear 可清除以节省 token”。
- 管道会话持久化到 `sessions/`，靠 meta 的 `mode` 字段区分。

**影响文件**：
- `core/session.py`：加 `latest_by_mode()`。
- `core/ui.py`：重写 `print_help_for_mode()`，`export_session_markdown` 按 mode 适配角色名。
- `chat/commands.py`：大改，返回 `switch_to` / `trigger_input`。
- `chat/main.py`：大改，统一模式循环。
- `pipeline/runner.py`：精简为 `PIPELINES` + `parse_file_arg`，删除 `interactive_loop` 等。

**结构隐患**：`chat/` 目录名不再准确，实际是三模式入口。暂不改名。

## v0.3.1 · 管道自动新建会话

**变动**：`main.py` 模式切换处判断。

**行为**：
- `/chat`：复用内存会话，没有则加载最近或新建。
- `/anima` `/minimax`：每次进入都新建会话，旧会话保留在 `sessions/`。
- 在同一管道内打 `/anima` 只提示“已经在 anima 模式”，不新建；想新建用 `/new`。

**决策**：保持现状，不在同模式内重复新建，避免误触。

## 关键决策汇总

| 决策 | 选择 | 理由 |
|---|---|---|
| API | Chat Completions | 兼容性最好，未来可换 Responses |
| 管道上下文 | 默认开启，持久化 | 用户要迭代提示词 |
| 管道校验 | 流式输出 + 最后校验 | 校验需完整文本 |
| 多会话存储 | JSONL 分文件 | 好读好修 |
| 模式切换 | 同级 `/chat` `/anima` `/minimax` | 符合人类习惯 |
| 聊天 `/clear` | 删除 | 用户靠 `/new` 或手动删文件 |
| 管道 `/clear` | 保留 | 对 token 敏感 |
| `//` 转义 | 删除 | 无需求 |
| 鲸鱼娘 prompt | 内置，身份边界约束 | 日常保持角色，技术问题如实答 |
| 启动参数 | 只处理固定项 | 交互命令手动敲 |
